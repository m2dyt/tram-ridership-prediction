# Источники городских данных, погоды и событий

Дата проверки: 21.09.2026. Решение пользователя: разрешено использовать любые подходящие открытые наборы с [data.mos.ru/opendata](https://data.mos.ru/opendata), включая метро и пересадочные узлы. Выбор конкретных наборов определяется задачей и качеством данных. Реализованы адаптеры Open-Meteo, WeatherAPI, KudaGo, Timepad, снимки и импорт GeoJSON Москвы. Точные текущие команды и ограничения: [OPERATIONS.md](OPERATIONS.md); сезонная база пока не использует эти признаки.

## 1. Городские данные

В каталоге data.mos.ru ищем следующие категории. Это список потребностей, а не утверждение, что для каждой уже найден доступный набор.

| Приоритет | Что искать | Для чего использовать | Что проверить |
| --- | --- | --- | --- |
| P0 | Остановки наземного транспорта, трамвайные маршруты | Привязка посадок, порядок остановок и участки | Направление, повторные остановки, даты действия, соответствие внешних ID |
| P0 | Станции и входы метро, МЦК, МЦД | Признаки близости пересадки и дополнительные слои карты | Вход и станция — разные объекты; координаты, период работы |
| P0 | Пересадочные узлы и хабы | Группировка связанных остановок и станций | Какие виды транспорта соединяет узел, дубли объектов |
| P0 для occupancy | Подвижной состав, вместимость, рейсы/расписания, телеметрия | Разделение пассажиров по вагонам и расчёт времени между остановками | Наличие этих данных на портале не подтверждено; при отсутствии нужен другой источник |
| P1 | Учебные заведения, рабочие/торговые центры, учреждения культуры, парки, спортивные площадки | Контекст спроса и назначения поездок | Актуальность, часы работы, точность геометрии |
| P1 | Перекрытия, ремонт, изменения движения, мероприятия | Временные изменения сети и спроса | Начало/конец действия и когда информация была опубликована |

**Результат проверки:** страница каталога не загрузилась через исследовательский инструмент, прямой запрос из локального окружения завершился `ConnectError`. Поэтому ID наборов, актуальные схемы, необходимость ключа и доступность API здесь не выдумываются. Перед реализацией адаптера открыть доступный каталог, выбрать карточки и зафиксировать точные ID, URL выгрузки/API, условия использования и версию. Если API недоступен, подходит официальная файловая выгрузка с тем же паспортом происхождения.

Для каждого набора создаётся запись реестра: `provider`, `dataset_id`, `source_url`, `title`, `source_version`, `published_at`, `retrieved_at`, `valid_from/to`, `content_sha256`, `license_url`, `attribution`, `schema_version`, `coverage`, `quality_notes`. Неизвестное время публикации остаётся `null`; его нельзя заменить временем события. Поля реестра относятся к будущему конвейеру источников, а не к текущему `manifest.json`.

Географические признаки: расстояние от остановки до входа метро, наличие узла пересадки, число доступных видов транспорта и типы объектов вокруг остановки. Радиус и способ расчёта версионируются. Расстояние по прямой — приближение доступности, не фактическое время пешей пересадки. Близость метро не доказывает число пересевших пассажиров. Текущую сеть нельзя применять к историческому периоду без проверки дат действия.

## 2. Погодные API

| Источник | Доступ и назначение | Проверка |
| --- | --- | --- |
| **Open-Meteo — первый вариант** | JSON-прогноз по координатам; температура, осадки, снег, ветер. Бесплатный некоммерческий доступ без ключа; лимиты и коммерческий доступ — по условиям поставщика. [Документация](https://open-meteo.com/en/docs), [условия доступа](https://open-meteo.com/en/pricing) | Прямой GET вернул HTTP 200 и 48 часовых точек для Москвы. |
| **WeatherAPI.com — альтернативный адаптер** | `/forecast.json`, `/current.json`, `/history.json`; нужен API-ключ, глубина истории и горизонт зависят от плана. [Документация](https://www.weatherapi.com/docs/) | Документация проверена; запрос с ключом не выполнялся. |

Проверенный запрос Open-Meteo:

```http
GET https://api.open-meteo.com/v1/forecast?latitude=55.75&longitude=37.62&hourly=temperature_2m,precipitation,wind_speed_10m&forecast_days=2&timezone=Europe%2FMoscow
```

Шаблон WeatherAPI.com:

```http
GET https://api.weatherapi.com/v1/forecast.json?key=<API_KEY>&q=55.75,37.62&days=3
```

Ключ хранить только в backend, исключить из логов и клиентских переменных Vite. Регистрация и платные подписки в этой итерации не выполнялись.

**Проектные правила использования:** сохранять координаты/ячейку, единицы измерения, `valid_time`, время выпуска модели (если предоставлено), время получения и `available_at`. Не путать техническое `generationtime_ms` с датой выпуска прогноза. При отсутствии подтверждённого времени доступности использовать первое фактическое получение и соответствующее ограничение backtesting.

Для проверки «что было известно тогда» нужны архивы отдельных выпусков, а не фактическая погода, скачанная после периода прогноза. Open-Meteo различает архив непрерывного ряда и отдельных запусков моделей; выбор описан в [Historical Forecast API](https://open-meteo.com/en/docs/historical-forecast-api). Время инициализации модели само по себе не подтверждает время публикации результата.

На горизонте суток можно использовать доступный краткосрочный прогноз. На месяц/год — только доступные на `as_of` климатические/сезонные сценарии с явной маркировкой либо модель без погоды. Нельзя растянуть двухдневный прогноз на год. При сбое источника сохраняются причина отсутствия признака и время последнего успешного получения.

## 3. API городских мероприятий

| Источник | Что брать | Доступ и результат проверки |
| --- | --- | --- |
| **KudaGo — первый кандидат** | Москва (`location=msk`), даты, категории, место, координаты и ссылка. `/public-api/v1.4/events/`; детализация места через `expand`. | Публичный API описан в [официальной документации](https://docs.kudago.com/api/). Прямой запрос из текущего окружения завершился `ConnectTimeout`; работа загрузчика пока не подтверждена. При использовании данных сохранять ссылки на первоисточник по условиям поставщика. |
| **Timepad — дополнительный кандидат** | `/v1/events`: город, временные фильтры, место, начало/конец, ссылка. | [Страница метода](https://dev.timepad.ru/api/get-v1-events/) допускает публичное чтение без авторизации, но [общая документация](https://dev.timepad.ru/api/what-api-can/) указывает токен. Пробный анонимный GET вернул HTTP 403. Для интеграции нужна проверка доступа с действующим токеном; публичный доступ не обещаем. |

Запрос KudaGo по документации:

```http
GET https://kudago.com/public-api/v1.4/events/?location=msk&page_size=100&fields=id,title,dates,place,categories,site_url&expand=place,dates&actual_since=<UTC_UNIX_SECONDS>&actual_until=<UTC_UNIX_SECONDS>
```

Запрос Timepad по документации:

```http
GET https://api.timepad.ru/v1/events?cities[]=Москва&limit=100&starts_at_min=<RFC3339>&starts_at_max=<RFC3339>
```

URL-параметры кодирует HTTP-клиент. Текущая реализация ограничена первой страницей до 100 событий; следующая страница KudaGo явно отмечается предупреждением. События с несколькими сеансами разворачиваются в отдельные временные интервалы. Неизвестные координаты, отмены, переносы и круглосуточные/бессрочные события обрабатываются отдельно.

**Проектные признаки:** число активных событий рядом с остановкой, категория, время до начала, время после окончания, расстояние до площадки, размер площадки — только когда он известен. Посещаемость и число пассажиров не равны числу событий, проданным билетам или лимиту площадки. Нельзя использовать итоговую посещаемость как заранее известный признак.

Дедупликация сначала по `(provider, event_id, occurrence)`, затем сопоставление площадки, времени и названия между поставщиками с сохранением исходных ID. Для исторической проверки сохраняются версии анонсов: сегодняшняя редакция старого события не считается известной в прошлом. Отсутствие события в выдаче одного поставщика не означает отсутствие городских мероприятий.

## 4. Встраивание в чистую архитектуру

Реализовано: `infrastructure/sources.py` — HTTP/файловые адаптеры; `application` — порты источников, загрузка, проверка, снимок признаков; `domain` — время, идентификаторы, инварианты; `tram_ml` — расчёт признаков и оценка пассажирообмена без сетевых вызовов. UI получает подготовленные данные через наш API. GET прогноза не обращается к поставщикам.

Текущая загрузка сохраняет нормализованные записи и метаданные доступности; для GeoJSON также SHA-256 файла. Сырые ответы HTTP автоматически не архивируются. Повтор создаёт новый снимок. Реализованы таймауты, ограничения размера и состояние `unavailable`; автоматические повторы, полный обход каталога и расписание остаются расширениями после проверки доступа и лимитов. Обновление в расписании задаётся после проверки лимитов и реальной частоты изменения источника; сейчас фоновые загрузки не включены.

Перед включением признака: доказать наличие данных, доступных на `as_of`, проверить покрытие маршрутов и сравнить модель с этим признаком и без него на одинаковых временных folds. Геоданные и внешние факторы не заменяют трамвайные наблюдения.
