# Практические сценарии

Команды выполняются из корня с активированной `.venv`. Первичная установка — в [README](../README.md).

## Демонстрация

```powershell
python -m tram.cli demo data/demo-complete
python -m tram.cli publish data/demo-complete
python -m tram.cli replay-trip data/demo-complete/trip-plan.json data/demo-complete/trip-events.jsonl
```

`demo` создаёт новый каталог, четыре синтетические остановки, три ряда наблюдений, запросы прогнозов, план/события рейса, запрос погоды и исторические отсечки. Если каталог существует, он сохраняется: используйте его или выберите новое имя. На следующий день генерируйте новый набор для актуальных демонстрационных дат. Повторная публикация неизменённого набора безопасна.

В интерфейсе подключиться ключом operator из локального `.env`, выбрать «Прогноз» и нажать «Рассчитать прогноз». Worker должен работать. Ключ viewer позволяет только чтение. При перезагрузке страницы ключ вводится заново; он не записывается в localStorage и сборку.

## Отчёты качества без обучения

```powershell
$demoManifest = Get-Content data/demo-complete/manifest.json -Raw | ConvertFrom-Json
$demoOrigins = Get-Content data/demo-complete/evaluation-origins.json -Raw | ConvertFrom-Json
$demoRevision = $demoManifest.capabilities.dataset_revision_id
python -m tram.cli evaluate --dataset $demoRevision --profile demo-validations-day --origin $demoOrigins.day
python -m tram.cli evaluate --dataset $demoRevision --profile demo-validations-month --origin $demoOrigins.month
python -m tram.cli evaluate --dataset $demoRevision --profile demo-validations-year --origin $demoOrigins.year
```

Для нескольких folds повторить `--origin` в возрастающем порядке. Все тестовые горизонты должны целиком входить в историю и завершиться к текущему времени. Максимум 100 отсечек и миллион итоговых точек на отчёт. Каждый вызов публикует новый UUID отчёта. Пересекающиеся folds считаются отдельными прогнозами. Нулевые ошибки на синтетических сезонных данных не означают точности на реальных маршрутах.

## Погода и мероприятия

```powershell
python -m tram.cli context-refresh data/demo-complete/context-request.json
```

В JSON `provider`: `open-meteo`, `weatherapi`, `kudago`, `timepad`; координаты и `from`/`to` обязательны. Окно положительное и не больше семи суток. Для погоды адаптер получает текущий трёхдневный выпуск провайдера; `from`/`to` задают фильтр для мероприятий, не заказ исторической погоды. Фактическое покрытие смотреть по времени нормализованных записей. Интерфейс сам формирует актуальный запрос.

Опциональные секреты в `.env`: `TRAM_WEATHERAPI_KEY`, `TRAM_TIMEPAD_TOKEN`. После изменения перезапустить API. При недоступности провайдера HTTP API возвращает 200 со снимком `status=unavailable`, CLI завершается с кодом 1. Никаких фоновых запросов по расписанию по умолчанию нет. Повтор — отдельный снимок, поэтому частоту задаёт оператор с учётом лимитов поставщика.

KudaGo/Timepad получают до 100 событий за запрос. В выдаче KudaGo наличие следующей страницы отмечается предупреждением; полный обход каталога сейчас не реализован. Сеансы разворачиваются отдельно. События без корректного интервала не включаются; их посещаемость не оценивается. Timepad не геокодируется автоматически.

## Геоданные data.mos.ru

Скачать официальный экспорт нужного набора (например, входы метро/хабы), привести к RFC7946 GeoJSON FeatureCollection с Point `[longitude,latitude]`. Не угадывать систему координат и поля. Указать реальный URL карточки и имена полей:

```powershell
python -m tram.cli import-geo data/metro.geojson --source-url "https://data.mos.ru/opendata/ID_НАБОРА" --category metro --id-field global_id --name-field Name
```

URL выше — шаблон, его обязательно заменить. Поддерживаются категории `metro`, `hub`, `poi`; лимит файла 50 MB. Повторяющиеся ID, некорректные координаты, геометрии кроме Point и устаревшее поле `crs` отклоняются. Нормализованные записи, ссылка и SHA-256 файла сохраняются в снимке. Сырые исходники хранить отдельно; локальный каталог `data/` не попадает в Git. API Москвы и реальные dataset IDs не подтверждены в текущем окружении.

## Рейсы, повтор и исправления

`POST /occupancy-trips` принимает полную последовательность опубликованного направления с ожидаемыми временами, ID вагона, исходным остатком, сценарием длительности, вместимостью либо `null`, обязательной конечной. `POST /occupancy-trips/{trip_id}/events` принимает следующую остановку, посадки и при наличии измеренные высадки. Схемы и ограничения — в Swagger.

Повтор одинакового `trip_id`/плана или `event_id`/события не пересчитывает пассажиров. Повтор возвращает **текущее** состояние; историческое состояние конкретного события находится в журнале `state_after`. Другое содержимое под тем же ID — 409. Пропущенную остановку нельзя незаметно перескочить. Время события и доступности должно быть хронологичным, future available_at отклоняется.

Исправления: подготовить новый `trip_id`, полный исправленный план и журнал, затем выполнить `replay-trip`. Старое состояние остаётся доступным. Если CLI прерван после нескольких событий, повтор того же журнала продолжает обработку идемпотентно. Переноса неизвестного остатка между двумя разными рейсами автоматически нет: он задаётся явно в initial_passengers.

## Исторические агрегаты наполненности

```powershell
$trip = Get-Content data/demo-complete/trip-plan.json -Raw | ConvertFrom-Json
python -m tram.cli export-occupancy data/occupancy-export --trip-id $trip.trip_id --revision occupancy-demo-v1 --from "2026-09-20T12:00:00+03:00" --to "2026-09-20T14:00:00+03:00" --metric occupancy --resolution hour
```

Даты в примере соответствуют демо, созданному 21.09.2026; для своего набора взять завершённые интервалы вокруг событий. Можно повторять `--trip-id` для нескольких вагонов одной сети и source_mode. Не включать одновременно старую и исправленную версию одного физического рейса; автоматического сопоставления разных trip_id нет.

После проверки экспорт публикуется `python -m tram.cli publish data/occupancy-export`. Он содержит профили истории и **не объявляет доступный прогноз** без достаточной истории и подготовленного профиля. Публикация делает этот набор последним для `/capabilities` без параметра; UI выбирает последнюю ревизию. Для возврата к другой ревизии используйте явный dataset_revision_id в API либо публикуйте новый полный согласованный набор.

Для ratio использовать `--metric occupancy_ratio`. Проезд с неизвестной вместимостью даёт `null` для всего затронутого бакета ratio, чтобы не скрыть неизвестную часть выборки. Нет завершённых проездов — `null`. Среднее считается по вагоно-секундам наблюдавшихся проездов, а не по всей продолжительности суток.

## CSV уже подготовленных агрегатов

```powershell
python -m tram.cli prepare-csv data/source-manifest.json data/aggregates.csv data/prepared
python -m tram.cli publish data/prepared
```

Точный заголовок UTF-8 CSV, разделитель — запятая:

```csv
profile_id,level,route_id,direction_id,stop_id,stop_sequence,segment_id,interval_start,interval_end,available_at,value,value_kind,estimation_method,missing_reason
```

Пустой value означает пропуск с обязательным missing_reason. Неизвестные пространственные поля пустые. Для `estimated` обязателен estimation_method. Манифест описан в [DATA_FORMAT](DATA_FORMAT.md). Конвертер потоковый; семантические проверки, порядок, дубли и полный охват проверяются при атомарной публикации. При ошибке конвертации остаётся незавершённый каталог без финального manifest.json; для повтора выбрать новый каталог. Это адаптер агрегатов, а не автоматическая расшифровка любых сырых таблиц организаторов.

## Выпуск транспорта

Калькулятор находится в «Наполненность» и `POST /scenarios/fleet`. Формулы: `headway = 60 × capacity × target_ratio / passengers_per_hour`, `vehicles = ceil(round_trip_minutes / headway)`. При нулевом спросе вагонов 0, интервал `null`. Вводится поток через самый загруженный участок одного направления, одинаковые вагоны, полный оборот с отстоем и доступный резерв. Это сравнение сценария с резервом, без автоматического изменения выпуска и оптимизации расписания.
