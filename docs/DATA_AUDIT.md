# Первичный аудит полученных московских наборов

Проверка **21.09.2026**, без обучения и без публикации в рабочую БД. Оба набора из пользовательской спецификации получены через **«Экспорт → набор JSON»** официального портала; отдельно скачаны JSON-паспорта. Архивы проверены, JSON распакован без изменения байтов. [Реестр источников](DATASETS.md), [журнал ссылок и контрольные суммы](DATA_LINK_CHECKS.json).

**Продолжение 22.09.2026:** по результатам этого аудита реализованы `prepare-metro` и `evaluate-metro`. GeoJSON, квартальная сетка, отчёт проблем, splits и сезонная база готовы; [результаты и правила](METRO_PIPELINE.md). Ниже сохранены исходные наблюдения аудита; причины спорных значений ещё не установлены.

## 62743: поток и длина истории

Фактические поля: `NameOfStation`, `Line`, `Year`, `Quarter`, `IncomingPassengers`, `OutgoingPassengers`, `global_id`. Паспорт описывает квартальную периодичность. Здесь `global_id` идентифицирует **строку наблюдения**, а не постоянную станцию для соединения с 624. Название станции без линии также не является достаточным ключом.

| Проверка | Результат | Значение для подготовки |
|---|---|---|
| Период | **2021-Q1 — 2026-Q2**, 22 квартала | Сохранять квартальную частоту. Это максимум 22 временные точки на ряд, не 6 448 точек одного ряда. |
| Различные станции/ряды | 263 названия; **315 пар «станция + линия»** | Нужен справочник устойчивых станционных ID и изменений сети. |
| Дубли | Нет повторов `global_id` и ключа «станция + линия + год + квартал» | Проверка относится к этой версии и точному совпадению строк. |
| Значения потока | Нет `null`, отрицательных или нецелых значений | Полнота значений внутри существующих строк не означает полноту временной сетки. |
| Нулевой поток | **193 строки** с нулём входов и выходов одновременно | Сохранить и исследовать причины; автоматически удалять или заменять на пропуск нельзя. |
| Полные ряды | **253** пары имеют все 22 квартала | Остальные ряды короче; открытие станции и ошибка/пропуск требуют разных правил. |
| Внутренние разрывы | 5 рядов, по одному пропущенному кварталу между первым и последним наблюдением | Не заполнять нулём без основания. |
| Состав сети | Есть МЦК и монорельс наряду с линиями метро | Зафиксировать состав учебной задачи; название набора не означает однородность транспорта. |

Внутренние разрывы:

- Кунцевская, Арбатско-Покровская линия — 2021-Q3.
- Смоленская, Арбатско-Покровская линия — 2021-Q3.
- Шелепиха, Большая кольцевая линия — 2021-Q3.
- Деловой центр, Большая кольцевая линия — 2023-Q4.
- Электрозаводская, Некрасовская линия — 2022-Q2.

Это обнаруженные отсутствующие записи, а не установленная причина. Причины нулей/разрывов и изменения линий нужно проверить отдельно. Индивидуальная сложная модель на 22 кварталах каждой станции легко переобучается; первым кандидатом может быть простая общая модель нескольких рядов с временной проверкой, после согласования идентичности объектов. Обученного кандидата пока нет; сезонная база оценена в последующем квартальном эксперименте.

## 624: входы метро и координаты

Основные поля: `global_id`, `Name`, `NameOfStation`, `Line`, `ExitNumber`, `Longitude_WGS84`, `Latitude_WGS84`, `ObjectStatus`, `geoData`, `geodata_center`. Координаты WGS84 в отдельных полях представлены строками, а `geoData` — массивом объектов Point. Это **не готовая GeoJSON FeatureCollection** для `import-geo`.

| Проверка | Результат | Действие |
|---|---|---|
| Уникальность | 1 177 уникальных `global_id` | Сохранять ID входа; не заменять ID названием станции. |
| Координаты | Во всех строках конечные числа в допустимом диапазоне; совпали с единственным Point в `geoData` с допуском 1e-7 | Можно готовить отдельный конвертер в RFC7946, сохранив свойства и происхождение. Это не проверка точности положения на местности. |
| Совпадающие координаты | 10 групп, 13 дополнительных записей | Не удалять автоматически: совпадающая точка не доказывает дубликат входа. |
| Статус | 1 165 «действует», 12 «временно закрыт» | Не терять статус; фильтр для текущего расчёта задаётся явно. |
| Территория | 1 166 «да», 11 «нет» в `OnTerritoryOfMoscow` | Наличие пригородных объектов учитывать по постановке, не считать ошибкой координат. |
| Пропуски | У 11 записей отсутствуют AdmArea/District; некоторые поля автоматов оплаты почти полностью пусты | Для начального географического признака эти поля не обязательны; правила пропусков описать по назначению. |
| Географические группы | 258 названий, 305 пар «станция + линия» | Входов на станцию несколько; соединение не должно размножать поток. |

## Соединение и временная доступность

Точное совпадение `NameOfStation + Line` найдено у **299 из 315** рядов потока; **16** не совпали с текущим геосправочником. Это диагностическая проверка, не окончательная таблица соответствия. Сравниваются история за 2021–2026 годы и география сентября 2026 года; нужны версии и изменения названий/линий. Автоматически отбрасывать 16 рядов или соединять их «по похожести» нельзя.

Скачанная актуальная версия может содержать поздние исправления старых кварталов. Дата квартала не доказывает время публикации его значений. Для строгой проверки `as_of` нужны исторические релизы/время доступности; до этого возможен **ретроспективный учебный эксперимент на текущем снимке** с явным ограничением. Текущую географию нельзя без обоснования представить известной в 2021 году.

## Выполнение действий по результатам аудита

1. Правила сохранения нулей, разрывов и статусов реализованы. Проверка их причин и таблица соответствия физических станций/переименований остаются следующей предметной работой; 16 связей не подтверждены.
2. Адаптеры 624 → Point FeatureCollection и 62743 → квартальные ряды реализованы. ID стабилен для точной пары названий, но не заменяет физический ID. Оригиналы не изменены.
3. Цель эксперимента зафиксирована: следующий квартал входящего потока. Исходные входы и выходы сохранены раздельно; для оценки выходов есть отдельный параметр команды.
4. Train 2021–2023, validation 2024, test 2025-Q1 — 2026-Q2 и база «тот же квартал прошлого года» реализованы. Все ряды остаются в плотной сетке; отсутствующая опора даёт null, исключения и покрытие видны в отчёте.
5. После проверки данных подготовить признаки и процесс обучения по [глобальному плану проекта](../00_ГЛОБАЛЬНЫЙ_ПЛАН_К_ЭТАЛОНУ.md). Метро остаётся отдельным учебным экспериментом; реальная трамвайная наполненность потребует своих наблюдений.

Машинные результаты первичного аудита сохранены локально в `data/quality/moscow-20260921/audit.json`; контрольные суммы входов включены. Метод проверки: чтение JSON без изменения, подсчёт уникальных ключей/типов/нулей, кварталов между первой и последней записью ряда, проверка координат и точное соединение строковых названий. На этапе первичного аудита нормализация не выполнялась; последующая подготовка описана в [METRO_PIPELINE.md](METRO_PIPELINE.md). Заполнение неизвестных значений и обучение не выполнялись.
