# Машинное обучение и прогнозный конвейер

Документ описывает, как устроен прогноз почасовых посадок по трамвайным маршрутам: данные, признаки, рабочая модель сервиса, проверка, хранение версий и подключение к серверу. Все цифры ниже получены на метках конкурса за 1 января – 31 октября 2025 года и воспроизводятся командами из раздела 8.

---

## 1. Задача и данные

- Объект прогноза: число посадок (валидаций) по маршруту за каждый час. Маршруты `1, 5, 7, 11, 12, 17, 25, 26, 28, 50`.
- Данные: `dataset/labels/labels_day_train.csv` и `labels_day_test.csv` (маршрут, дата, час, посадки), всего около 57 тыс. строк. Час без строки означает ноль посадок.
- Метрика: WAPE = Σ|факт − прогноз| / Σ факт, WAPE-score = 1 − WAPE. Функция потерь модели MAE, она прямо уменьшает числитель WAPE.
- Остановки: валидация не знает остановку, поэтому значения по остановкам это доля маршрута по весам остановок (`backend/src/tram/domain/allocation.py`).

## 2. Календарь

Признаки дня берутся из официального производственного календаря РФ на 2024–2027 годы: `ml/training/tram/production_calendar_ru.csv`, модуль `ml/training/tram/calendar.py`. Таблицу загружает `scripts/fetch_production_calendar.py` с isdayoff.ru (сервис собран по постановлениям Правительства о переносе выходных). Для 2025 года таблица совпадает со списком праздников, который команда составила вручную.

- Праздник: выходной из блока подряд идущих выходных, в котором есть праздник по ст. 112 ТК РФ (1–8 января, 23 февраля, 8 марта, 1 и 9 мая, 12 июня, 4 ноября) или будний выходной (перенос).
- Сокращённый день: рабочий день перед праздником.
- Рабочий выходной: суббота или воскресенье, объявленные рабочими (1 ноября 2025, 20 февраля 2027).
- Эффективный день недели `dow_effective`: праздник считается воскресеньем, рабочий выходной пятницей.

За пределами таблицы выходными считаются суббота, воскресенье и праздники по ст. 112, переносы там неизвестны. Когда выйдет постановление на новый год, нужно запустить `python scripts/fetch_production_calendar.py --years 2024 2025 2026 2027 2028`.

## 3. Рабочая модель сервиса (рецепт `adaptive_v2`)

Код: `ml/training/tram/adaptive.py` (одни и те же функции при обучении и на сервере), запуск обучения `ml/training/tram/service.py`.

1. **База из свежих данных.** Для каждой тройки «маршрут, эффективный день недели, час» база это медиана посадок за последние 28 дней истории того же сезона (лето или не лето). База пересчитывается из истории на момент прогноза, поэтому ремонт путей, новое расписание или осенний рост попадают в прогноз сами, без ручных коэффициентов.
2. **Модель поправки.** `HistGradientBoostingRegressor` (функция потерь MAE, 80 деревьев, шаг 0,05, глубина 4, не меньше 200 строк в листе, L2 = 1) учит разницу «факт − база». Признаки: календарь (16 признаков) и профиль (долгая медиана, свежая медиана, свежая медиана выходных и будних, разброс, отношение свежей медианы к долгой).
3. **Признаки только из прошлого.** При обучении каждая неделя получает признаки профиля из истории строго до своего начала, как будет на сервере. Тест `test_profile_features_never_look_into_the_future` проверяет, что изменение будущих данных не меняет признаки.
4. **Выбор.** Последние 8 недель откладываются. Модель поправки включается, только если на них она точнее одной базы. Иначе файл модели обслуживает базу.
5. **Диапазон прогноза.** По ошибкам на отложенных неделях отдельно для ночи (0–5, 22–23 ч), дня и часов пик (7–9, 17–19 ч) берутся 10-й и 90-й процентили. Диапазон = прогноз + эти поправки, он не опускается ниже нуля и всегда содержит сам прогноз. Номинальное покрытие 80 %. Покрытие проверяется так: процентили считаются по первой половине отложенных недель, попадание факта в диапазон измеряется на второй.
6. **Финальное обучение.** После проверки модель переобучается на всей истории и выгружается как рабочая версия. Копия, обученная до отложенных недель, выгружается как `<version>-check` для честного отчёта о точности.
7. **Закрытые маршруты.** Если у маршрута за свежее окно нет ни одной посадки (маршрут 5), прогноз равен нулю.

### Почему так, а не прежняя схема

Прежняя модель стенда училась на январе–августе, сентябрь и октябрь в неё не попадали. База команды содержала ручные коэффициенты: маршрут 50 в выходные всегда 0, маршрут 7 в выходные всегда ×0,6, рост ×1,15, ×1,18 и ×1,04. Ремонт на маршруте 50 начался 6 сентября, то есть внутри проверочного периода, а коэффициенты роста подобраны с учётом осени. В рабочем сервисе такие числа остались бы навсегда, например после конца ремонта маршрут 50 в выходные продолжал бы получать ноль.

Честная проверка «как у живого сервиса» (профили каждую неделю пересчитываются только по прошлым данным, прогноз на неделю вперёд):

| Схема | WAPE сентябрь–октябрь | WAPE октябрь |
|---|---|---|
| Прежняя модель стенда | 9,88 % | 9,48 % |
| Таблица команды с ручными коэффициентами (знает будущее) | 9,63 % | 9,58 % |
| Сезонная база «неделей раньше» | 10,93 % | |
| База из свежих 28 дней | 9,28 % | 8,82 % |
| База + модель поправки, переобучение раз в месяц | 9,31 % | 8,58 % |

Отложенные 8 недель рабочего рецепта (6 сентября – 31 октября 2025): база 9,29 %, база + модель 9,22 %, выбрана модель. Диапазон 80 % накрыл 83,3 % фактических значений на последних 4 неделях. Настройки модели поправки выбраны из четырёх вариантов на двух окнах проверки (8 и 4 недели): прежние настройки (160 деревьев, глубина 6) на 8 неделях проигрывали базе, осторожные выигрывали на обоих окнах.

### Погода

Погода в рабочую модель не входит. Даже с фактической почасовой погодой Open-Meteo, которая на момент прогноза неизвестна, ошибка не уменьшилась: 9,96 % против 9,88 % на сентябре–октябре, 9,24 % против 9,29 % и 9,57 % против 9,48 % на октябре. С прогнозом погоды было бы не лучше. Сервер отказывается загружать версию модели с `use_weather: true`, потому что у него нет источника прогноза погоды и он подставил бы средние значения.

## 4. Прогноз по остановкам

Сервер прогнозирует маршрут целиком и делит прогноз по остановкам пропорционально их долям за последние 28 дней истории остановок. Обработчик заданий передаёт модели все остановки маршрута в одном вызове вместе с историей маршрута. Сумма по остановкам равна прогнозу маршрута. Без модели (или если её нет) остановки считает сезонная база «неделей раньше», у неё ночью бывают пустые часы.

## 5. Конкурсная модель

Отдельно сохранён конвейер хакатона (`ml/training/tram/cli.py`, `baseline.py`, `models.py`): статичные профили с ручными коэффициентами и CatBoost или HistGradientBoosting на остатках. Он нужен для конкурсной отправки на ноябрь–декабрь (`scripts/validate_submission.py`) и в сервисе не используется.

## 6. Версия модели (бандл)

Версия лежит в `models/tram/<version>/`: `estimator.joblib`, `features.json`, `config.json`, `metrics.json`, `manifest.json` (SHA-256 каждого файла) и `model-card.md`. У рабочей модели в `config.json` есть `recipe: adaptive_v2`, `recent_days`, `params`, `spatial_levels: ["route", "stop"]`, `training_history_start`, `training_history_end`, `holdout_start`. В `metrics.json` лежат ошибки на отложенных неделях (`holdout.base_wape`, `holdout.model_wape`, `selected`) и параметры диапазона (`intervals`). Активную версию задаёт `models/tram/active_version.txt`.

## 7. Подключение к серверу

- `ArtifactPredictor` (`backend/src/tram/infrastructure/ml/artifact_predictor.py`) для рецепта `adaptive_v2` строит часы истории из наблюдений (пропуск считается нулём), считает профили на момент прогноза, прогноз и диапазон. Диапазон попадает в поле `prediction_interval` значения прогноза.
- Флаг `prediction_interval_available` профиля в данных описывает сезонную базу из набора данных и остаётся `false`. Диапазон приходит только в расчётах обученной моделью.
- Если версия модели не проходит проверку контрольных сумм или не загружается, расчёты, закреплённые за ней, завершаются ошибкой, а не подменяются сезонной базой.

## 8. Команды

```bash
# Рабочая модель: проверка на 8 неделях, выбор, диапазон, финальное обучение, две версии
python -m ml.training.tram.service --data-dir dataset --version service-test --set-active

# Отчёт о точности проверочной версии на экран «Качество» (после публикации данных)
python scripts/evaluate_check_model.py service-test-check

# Обновить производственный календарь
python scripts/fetch_production_calendar.py --years 2024 2025 2026 2027

# Конкурсная модель и проверка файла отправки
python -m ml.training.tram.cli --model histgradient --cpu --no-weather --no-route-features
python scripts/validate_submission.py ml/predictions/submission.csv
```

## 9. Как часто переобучать

Профили пересчитываются при каждом прогнозе сами. Модель поправки стоит переобучать раз в месяц или после загрузки новых данных: в проверке переобучение раз в месяц снизило ошибку октября с 8,78 % до 8,58 %. На стенде это делает `scripts/train-model.sh`: новые данные или новый рецепт дают новое имя версии, старая версия не перезаписывается.
