# Журнал реализации и ревью

## Шаг 1 — структура и окружение

План:
1. Проверить исходное состояние, инструкции и согласованный контракт.
2. Зафиксировать направление зависимостей и границы реализации.
3. Создать пакеты backend/ML, конфигурацию зависимостей и исключения Git.
4. Проверить окружение и пересмотреть архитектуру до реализации сценариев.

Исходное состояние: два документа, один коммит, незакоммиченных изменений нет. Дополнительных AGENTS.md нет. Python 3.12 и uv доступны; Docker Desktop установлен, daemon первоначально не запущен.

Ревью: правила времени и пространственных ключей должны находиться в domain; SQL, HTTP и сериализация — в адаптерах. ML не должен принимать будущие наблюдения как лаги. JSON-проекции чтения разрешены отдельно от командной модели. Обучение исключено из этой итерации. Детали решения — ADR 0001.

Первичная загрузка зависимостей блокировалась сетевыми таймаутами. После установки пользователем проверено локальное `.venv`: Python 3.12.5, все runtime/dev зависимости импортируются, `pip check` не обнаруживает конфликтов. Используется один `requirements.txt`. Точный lock-файл пока не сформирован.

## Шаг 3 — хранение и сценарии

План:
1. Описать порты хранилища и сценарии приложения.
2. Реализовать SQL-адаптер и явную миграцию десяти таблиц.
3. Проверить идемпотентность, lease/fencing, атомарную публикацию и внешние ключи.
4. Повторить критические проверки на PostgreSQL.

Ревью: исправлено обращение к неопределённому `Text` в сгенерированной миграции. Очередь захватывает не более одного задания с `FOR UPDATE SKIP LOCKED`. Потерявший lease worker не может завершить или продлить чужое задание. Ошибка вставки точек откатывает всю публикацию. Создание запуска и ключа идемпотентности выполняется в одной транзакции; PostgreSQL advisory lock защищает конкурентный повтор.

Проверки: SQLite — идемпотентность, rollback, lease, лимит попыток, внешние ключи, курсоры и согласованность карты/графика. Результат: подключены все 15 операций. YAML является источником Swagger и входных схем. Запросы с неизвестными/повторными query-параметрами, неверными типами, датами без смещения, дублирующимися JSON-полями и некорректными ключами отклоняются. Размер команды ограничен 64 KiB. Ревью: исправлено разрешение ссылок JSON Schema; код MODEL_UNAVAILABLE приведён к согласованному 422. Regression-тест проверяет смену queued → succeeded между страницами. Неожиданные ошибки не раскрывают SQL/секреты; недоступность соединения и пула возвращает 503. Проверяется срок действия маршрута на всём горизонте.

Проверки: доступ по ролям, идемпотентность 202/200/409, готовность результатов, подписанные курсоры, строгие даты, схемы ответов всех операций, безопасные 500/503. Сутки, месяц и год проходят путь HTTP → application → SQL → worker → HTTP. Карта и график читают одинаковые опубликованные значения.

Результат: `tram demo <новый каталог>` создаёт детерминированные синтетические данные на текущую дату и запросы для трёх горизонтов. `tram publish <каталог>` валидирует JSON/OpenAPI и бизнес-правила, читает JSONL последовательно, вставляет наблюдения пакетами по 500 строк. SQL-адаптер реализует отдельный порт публикации. SHA-256 охватывает манифест и порядок записей. Версии сети и набора неизменяемы.

Ревью: дубли, неполные/пропущенные интервалы, будущая доступность, неверные связи и несовместимые единицы отклоняются; ошибка в конце потока откатывает весь импорт. Пропуски передаются явно, нулями не заполняются. PostgreSQL advisory locks защищают конкурентный повтор версии. При повторе проверяется весь входной поток, а не только ID. Обучение, реальные пассажирские данные и вымышленные метрики точности не добавлялись.

Проверки: восемь тестов публикации/демо и отдельный PostgreSQL-тест конкурентной публикации. Для демоданных все три горизонта дают полный набор точек; `source_mode=demo` сохраняется. Публикация отчётов backtesting в этот формат не входит.

### Шаг 13. Экспорт наполненности

План: журнал → завершённые проезды → среднее по времени → prepared bundle → публикация.

export-occupancy строит segment-профили истории, отдельно усредняет occupancy и ratio с индивидуальными вместимостями. Нет проезда/вместимости — объяснённый null; значение estimated, качество unverified, provenance trip_ids. Профиль прогноза автоматически не объявляется. Новая доступность ставится на время экспорта, не задним числом.
