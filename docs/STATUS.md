# Состояние реализации

Снимок проанализирован 26.09.2026 на `main` commit `1489c15` перед созданием плана. Код в этой ветке исследован, тестовый набор в этой работе не запускался. Ветка описывает текущее содержимое репозитория, а не факт отправки/оценки решения на хакатоне.

## Общая оценка

У проекта две разные модельные задачи. `ml/training/train_tram.py` готовит конкурсный почасовой прогноз маршрутов и формирует CSV. `ml/training/prepare.py`, `train.py`, `evaluate.py` работают с отдельной квартальной задачей метро. Backend API и worker архитектурно имеют `Predictor` port, однако composition root подаёт worker `SeasonalNaive`; конкурсная/metro модель не подключена к HTTP inference.

На момент анализа в `ml/predictions/submission.csv` было 14 640 строк данных и ожидаемый разделитель `;`. Это структурный признак файла, а не проверка соответствия всем test-ключам или результата на лидерборде. Фактическое наличие конкурсного `train.csv/test.csv` не подтверждено: директория `dataset/` исключается из Git. В проекте есть примеры погоды/KudaGo и подготовленные источники 624/62743, но они не заменяют конкурсные passenger labels.

Корневые README/часть старых документов до этой ветки утверждали, что обучение не реализовано; это было устаревшим после добавления тренера трамваев. Сводный план и карта следующих шагов: [HACKATHON_READINESS_PLAN.md](HACKATHON_READINESS_PLAN.md) и [ML_BACKEND_TASKS.md](ML_BACKEND_TASKS.md).

## Примечания по метрикам

Спецификация задаёт конкурсный WAPE-score: `max(0, 1 - sum(abs(y - y_hat)) / sum(y))`. В PDF указаны ориентир baseline около 0.48 и порог высшей категории выше 0.88. В ответах организатора указано, что нулевой маршрут 5 оставляет заявленную максимальную метрику около 0.9935. Эти значения — критерии и разъяснения, а не результаты независимой проверки этого репозитория. Не переносить в README точность модели, пока нет локального отчёта, хешей входов/кода и подтверждения платформы.

## Данные и ограничение детализации

Организаторы подтвердили, что участникам не удалось надёжно сопоставить валидации остановкам, что дополнительные связи факультативны, и что основной критерий — общий поток. `bus_stop_no`, `place_id`, `bus_exit_no` нельзя считать однозначными идентификаторами без полного словаря. В прогноз погоды для разрешённой конкурсной ретроспективы можно включить фактический архив, но operational inference и live backtest должны использовать выпуск погноза, доступный до времени прогноза.

Групповой расчёт occupancy в приложении — отдельная оценочная функция: `после = до + вошли − вышли`. Без независимых наблюдений высадок, идентификатора рейса/вагона и вместимости полученную наполненность нельзя считать точной целевой меткой для обучения.
