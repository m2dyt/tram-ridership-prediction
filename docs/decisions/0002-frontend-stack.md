# ADR 0002: React на JavaScript, Vite и OpenStreetMap

Статус: требования к React/JavaScript/Vite/OSM подтверждены пользователем 21.09.2026; Leaflet выбран как проектное решение для первой карты. Frontend реализован в frontend/; сборка и основные сценарии проверены.

## Решение

- React, обычный JavaScript и JSX (`.js`, `.jsx`), сборка и dev-server Vite. Прежнее предложение TypeScript заменено этим решением.
- Картографические данные/подложка OpenStreetMap. Для отображения первой версии — Leaflet: слои GeoJSON, маршруты, остановки, метро/хабы и окраска участков по наполненности.
- OSM — источник картографических данных, а не сборщик и не API пассажиропотока. Маршруты, версии сети и значения показателей загружаются из backend; подложка не является источником трамвайной телеметрии.
- API-клиент, состояние фильтров, виджеты карты/графика и форматирование выделяются отдельно. Обработка сети, погоды и событий остаётся на backend. Расчёт остатка пассажиров не дублируется в React.

[Vite](https://vite.dev/guide/) поддерживает шаблон `react` для JavaScript. [Leaflet](https://leafletjs.com/examples/quick-start/) показывает подключение OSM-подложки. Версии Node и пакетов выбираются при создании frontend по актуальным требованиям, после чего фиксируется `package-lock.json`.

## Слои и состояние экрана

Порядок: подложка → участки сети → окраска по выбранному запуску/интервалу → остановки → необязательные метро/хабы/события. Общий state хранит `dataset_revision_id`, `network_revision_id`, `run_id`, показатель, профиль, маршрут, направление и время. Карта и график читают один запуск. При смене фильтров старые запросы отменяются или их ответы игнорируются.

Подписи различают валидации, оценку посадок и оценку наполненности; `estimated`, `demo`, `stale` и пропуски видны пользователю. Разные сценарии длительности поездки обозначаются как сценарии, а не как гарантированные границы ошибки. Ключи внешних API не попадают в bundle и переменные `VITE_*`.

## Подложка и атрибуция

В интерфейсе сохраняется видимая атрибуция `© OpenStreetMap contributors` со ссылкой на [OSM copyright](https://www.openstreetmap.org/copyright). Публичные стандартные тайлы не имеют SLA и не предназначены для массовой предварительной загрузки; действуют требования к кэшированию и запросам. Для демонстрации/эксплуатации заранее выбирается допустимый поставщик тайлов или собственный сервис согласно [OSM Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/).

URL подложки и атрибуция конфигурируются. При недоступности тайлов показывается понятная ошибка; сохранённые данные backend и график продолжают работать. Проверяются порядок координат GeoJSON `[longitude, latitude]`, высота контейнера карты, resize и отсутствие повторной инициализации слоя при рендере React.

## Следующие шаги

1. Создать `frontend` из шаблона Vite `react`, подключить ESLint и единый API-клиент.
2. Реализовать карту Leaflet, подключить выбранную подложку и GeoJSON backend.
3. Добавить общие фильтры, график, обработку пагинации и состояния загрузки/ошибки.
4. Добавить слои метро/хабов после публикации соответствующих справочников.
5. Проверить синхронность карты и графика, недоступную подложку, атрибуцию, мобильный размер и доступность элементов управления.


Реализация 21.09.2026: frontend готов в `frontend/`, React/JSX + Vite + Leaflet. Сборка раздаётся FastAPI или dev-сервером с API-прокси. См. [frontend README](../../frontend/README.md).
