# ADR 0001: границы первой реализации

Статус: принято для первой итерации. Основание: согласованный пользователем Python-стек и требование чистой архитектуры.

## Зависимости

```text
api / cli / worker (входные адаптеры)
           ↓
application (сценарии и Protocol-порты)
           ↓
domain (инварианты и неизменяемые объекты, только стандартная библиотека)

infrastructure → application/domain
tram_ml → domain
composition → все адаптеры для сборки приложения
```

Domain и application не импортируют FastAPI, Pydantic, SQLAlchemy, HTTP-клиенты или ML-фреймворки. API не выполняет SQL. ML не знает о HTTP и БД. Сборка зависимостей выполняется явно, без глобального подключения к БД при импорте. Направление зависимостей проверяется архитектурным тестом.

Командная часть использует типизированные dataclass-объекты и инварианты. Для чтения используются проекции JSON, соответствующие согласованному OpenAPI; это не ORM-сущности и не источник бизнес-правил. Входные публикации проверяются по контракту до сохранения. Не вводим универсальные base-repository, service-locator и иерархии CRUD-сервисов.

## Объём итерации

1. Воспроизводимое окружение, приложение FastAPI, настройки, ошибки, доступ viewer/operator.
2. Время и пространственные ключи; ML-основа без обучения: доступность наблюдений на as_of, календарные признаки, временные folds, MAE/WAPE, сезонная база.
3. Версии данных и сети, SQL-хранилище, миграции, загрузка подготовленного набора через CLI.
4. Сценарии чтения справочников/истории и сохранённых результатов, создание идемпотентного задания.
5. Отдельный worker для применения сезонной базы, атомарная публикация и защита от повторной обработки.
6. Контрактные, интеграционные и архитектурные проверки; инструкция запуска и журнал ревью каждого шага.

Обучение, подбор параметров, реальные прогнозы и заявления об их точности не выполняются. Сезонная база не имеет fit-этапа и явно маркируется is_baseline. Нет реальных данных — нет автоматически опубликованных capabilities или вымышленных результатов. Синтетические данные используются только в явно вызываемом demo и тестах.

PostgreSQL — рабочая БД. SQLite допускается только как быстрый адаптер интеграционных тестов; блокировки и очередь отдельно проверяются на PostgreSQL. Геометрия первой итерации хранится как валидированный GeoJSON; PostGIS и пространственные SQL-запросы запланированы на следующий этап при появлении требований к ним.

## Порядок работы

Перед каждым шагом записываем план; после — результат проверки и ревью в `docs/IMPLEMENTATION_LOG.md`. Изменения интерфейса описываются в контракте, не скрываются в контроллерах. Не выдаём исходный полный контракт за список уже проверенных реализаций: фактическое покрытие отражаем в README и тестах.

Основания для технических решений: [FastAPI DI](https://fastapi.tiangolo.com/tutorial/dependencies/), [SQLAlchemy sessions](https://docs.sqlalchemy.org/en/20/orm/session_basics.html), [uv lock/sync](https://docs.astral.sh/uv/concepts/projects/sync/).
