# Подготовка метро и квартальная сезонная база

Реализованы **`prepare-metro`** и **`evaluate-metro`**. Это отдельный файловый эксперимент на наборах Москвы 624/62743. Команды не читают `.env`, не подключаются к БД, не меняют трамвайные профили и не обучают модель. Зависимости уже входят в существующий requirements.txt. [Источники и первичный аудит](DATA_AUDIT.md).

## 1. Подготовка

Из корня проекта с активированной `.venv`:

```powershell
python -m tram.cli prepare-metro sources/data-mos/624/2026-09-21/data-624-11-09-2026.json sources/data-mos/62743/2026-09-21/data-62743-08-09-2026.json data/metro/moscow-20260922 --revision moscow-metro-20260922
```

Исходники уже скачаны локально. После клонирования получить их по [DATASETS.md](DATASETS.md). Рядом с каждым JSON нужен `provenance.json`: `provider: "data.mos.ru"`, строковый `dataset_id`, точный `source_url` карточки, `source_version`, `retrieved_at` со смещением времени и `artifacts: [{"file": "имя.json", "sha256": "хеш"}]`. Проверяются хеш исходника, типы значений, дата получения и завершённость кварталов к этой дате.

Выходной каталог **должен быть новым**. Для нового расчёта выбрать новое имя/ревизию. Исходники не меняются. Ввод проверяется до записи результата; при ошибке диска возможен незавершённый каталог — для повтора выбрать другой. `manifest.json` записывается последним; читатель проверяет хеши всех файлов. Предел отдельного файла — 50 MB, плотной сетки — миллион строк.

| Файл результата | Назначение |
|---|---|
| `manifest.json` | Тип `metro_research_bundle_v1`, ревизия, время, версии/хеши источников, ограничения и SHA-256 результатов. Это не manifest трамвайного `publish`. |
| `entrances.geojson` | RFC7946 Point FeatureCollection: ID, названия, координаты, станция/линия, статус и признак территории. Все входы сохранены, включая закрытые. |
| `series.json` | Реестр пар «станция + линия», ID ряда, диапазон наблюдений и точные географические совпадения. `physical_station_id=null`. |
| `quarters.jsonl` | Полная сетка «ряд × квартал»: входы/выходы отдельно, ID исходной строки, observed/missing, причина пропуска и флаги. |
| `quality.json` | Счётчики и полный список проблем, кандидаты линий для несовпадений, закрытые входы и совпадающие координаты. |

### Принятые правила качества

- ID — UUIDv5 от **точной пары исходных названий** в фиксированном namespace. Порядок строк и новые кварталы не меняют ID. Переименование создаёт другой ряд: объединение потребует проверенного crosswalk с периодами действия. Это не постоянный физический ID станции.
- Дубли `global_id` и «станция + линия + квартал» отклоняются. Несколько входов станции не размножают поток.
- Оба нулевых потока сохраняются с `zero_flow_unverified`. Причина нуля не выдумывается.
- Пропущенный квартал внутри ряда получает `null` и `missing_source_period`; до первого/после последнего наблюдения — `outside_source_span`. Это не утверждение о дате открытия или закрытия станции.
- Несовпадение получает `unresolved_geo_match`; ряд сохраняется. Линии с тем же точным названием станции перечисляются как кандидаты для проверки, не как принятые связи.
- Закрытые и находящиеся вне Москвы входы, одинаковые координаты сохраняются с исходными свойствами; прикладной фильтр должен быть явным.

GeoJSON совместим с `import-geo` при `--id-field global_id --name-field Name`. Автоматического импорта в БД нет. Общий importer оставляет только ID, название, координаты и категорию; статус не переносит. Для слоя действующих входов сначала создать отфильтрованную производную, сохранив исходный GeoJSON и правило фильтра.

## 2. Временное разбиение и базовый прогноз

```powershell
python -m tram.cli evaluate-metro data/metro/moscow-20260922 data/metro-evaluation/seasonal-20260922 --revision metro-seasonal-20260922 --train-start 2021-Q1 --validation-start 2024-Q1 --test-start 2025-Q1 --test-end 2026-Q3 --metric incoming
```

`--test-end` **не включается**: пример заканчивается на 2026-Q2. Train — 2021–2023, validation — 2024, test — 2025-Q1…2026-Q2. Интервалы непустые, последовательные, внутри подготовленной истории; train содержит минимум четыре квартала. Для выходящего потока указать `--metric outgoing` и новый каталог/ревизию.

| Файл результата | Назначение |
|---|---|
| `manifest.json` | Метод `metro_quarterly_seasonal_naive_v1`, метрика, ревизия и SHA-256 входного manifest, ограничения, `training_performed=false`. |
| `splits.json` | Границы train/validation/test, горизонт и протокол проверки. |
| `membership.jsonl` | Принадлежность строк разбиению и наличие целевого наблюдения. |
| `predictions.jsonl` | Для validation/test: факт, прогноз, опорный квартал, учебная отсечка, причины отсутствующих значений. |
| `scores.json` | MAE/WAPE по разбиениям в целом и по рядам, число точек, исключения и покрытие. |

База прогнозирует **один квартал** значением того же квартала прошлого года. Следующий прогноз рассчитывается на новой квартальной отсечке: завершённые периоды validation/test могут быть опорой для более позднего прогноза. Это rolling-origin проверка, не выдача всех тестовых кварталов из одной отсечки. Нет прошлогоднего значения — прогноз `null`; ноль или другой ряд вместо него не подставляются. География и погода базой не используются.

Режим **`retrospective_snapshot`**: факт самого прогнозируемого квартала и более поздние значения в его расчёт не попадают, но исходники взяты из актуального релиза. Историческая доступность исправлений/публикаций не доказана; для строгого backtesting нужны старые релизы и время их доступности. `forecast_origin` обозначает учебную отсечку, не реальную дату выпуска прогноза.

MAE — пассажиры на пару «станция + линия» за квартал. WAPE хранится долей; для процентов умножить на 100. При нулевой сумме фактов WAPE — `null` с причиной. `excluded_count` учитывает отсутствие факта или прогноза. `coverage_on_observed` — сравнимые пары / известные факты, а не вся плотная сетка. Нулевые наблюдения входят в оценку.

## 3. Проверенный результат

Подготовка: **1 177 входов, 315 рядов, 22 квартала, 6 930 точек**. Сохранены 6 448 наблюдений, 193 нулевые строки, пять внутренних пропусков и 477 периодов вне диапазонов рядов. 16 географических связей остаются неподтверждёнными.

| Разбиение, incoming | Сравнимые точки / известные факты | MAE | WAPE | Покрытие |
|---|---|---|---|---|
| Validation, 2024 | 1 185 / 1 209 | 169 433.63 | 8.51% | 98.01% |
| Test, 2025-Q1…2026-Q2 | 1 793 / 1 828 | 181 916.20 | 9.33% | 98.09% |

Это качество фиксированной базы на **метро**, не обученной модели или трамвайной наполненности. Отчёты лежат локально в `data/`; Git содержит код, правила и сводку. Данные с нулями, разрывами и изменениями сети ещё требуют предметного разбора; их причины не объявлены установленными.
