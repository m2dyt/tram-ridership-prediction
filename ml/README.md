# ml — прогноз, признаки и следующий этап обучения

Библиотека `tram_ml` устанавливается вместе с backend через `pip install -r requirements.txt -e .` из корня. **Сейчас здесь выполняется прогноз без обучения.** Нет `fit`, команды `train`, обученных весов или автоматического скачивания датасетов.

## Что происходит при прогнозе

1. Worker получает опубликованный профиль, пространственные ряды, окно прогноза и `as_of`; repository читает подходящую историю из БД.
2. Через порт `Predictor` вызывается `SeasonalNaive.predict`. Сутки/месяц используют предыдущую доступную неделю; год — предыдущий год.
3. Возвращаются `Prediction`: пространственный ключ, интервал, значение либо `null` с причиной отсутствия, время опорного наблюдения. Worker сохраняет результат, API отдаёт его frontend.

Входы — объекты `Observation`, `SpatialKey`, `Interval`, параметры горизонта и разрешения. Выход — набор `Prediction`. Внутри этого вычисления нет HTTP, SQL и записи файлов. Клиент не должен собирать входы из непроверенных CSV напрямую.

## За что отвечают модули

| Модуль в src/tram_ml | Роль сейчас | Что потребуется для обучения |
|---|---|---|
| `baseline.py` | Контрольный сезонный прогноз без подбора параметров | Оставить отдельным соперником кандидата, не заменить им обе стороны сравнения. |
| `features.py` | Календарь Москвы | Добавить согласованные лаги/статистики без будущих значений, правила неизвестных категорий. |
| `context.py` | Расстояния и выбор доступного контекста по месту/времени | Согласовать признаки с train/inference; текущая база эти признаки не использует. |
| `evaluation.py` | Полные временные folds и MAE/WAPE | Организовать обучение внутри каждого fold и независимое сравнение с baseline. |

Подробности и ссылки на каждый файл — [README библиотеки](src/tram_ml/README.md).

## Что делать дальше именно здесь

1. Получить готовый целевой ряд из [data](../data/README.md), решить, это квартальное метро 62743, трамвайные посадки или наполненность.
2. Зафиксировать временные splits, признаки и сезонную базу. Квартальных folds в текущей библиотеке нет; их нельзя заменить месячными без изменения постановки.
3. Реализовать отдельный внешний слой `ml/training/` и конфигурации `ml/experiments/` по [TRAINING_PLAN.md](../docs/TRAINING_PLAN.md). **Эти подпапки пока не созданы**, их названия описывают будущую работу.
4. Подключить выбранную обучающую библиотеку в существующие зависимости, обучить кандидат после готовности данных и сравнить его на отложенном периоде.
5. Сохранить версию/паспорт в [models](../models/README.md); только после ревью подключить загрузчик через backend.

Чистый пакет `tram_ml` пока зависит только от stdlib и `tram.domain`, это проверяет архитектурный тест. Зависимости будущего обучающего слоя нужно явно описать и проверить; не ослаблять ограничения domain/application. [Архитектура](../docs/ARCHITECTURE.md).

## Как проверить текущую часть

Из корня с активированной `.venv`:

```powershell
python -m pytest -q tests/test_domain_ml.py tests/test_context.py tests/test_evaluation_pipeline.py
```

Сквозная оценка опубликованного демонабора через `python -m tram.cli evaluate` описана в [OPERATIONS.md](../docs/OPERATIONS.md). Она сохраняет отчёт в БД и **не обучает** модель. Ошибки демо не являются качеством на реальных пассажирах.
