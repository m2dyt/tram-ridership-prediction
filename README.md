# ИИ-прогноз загрузки трамвайных маршрутов

## 🚋 Главный план проекта

**[Открыть глобальный план к эталонному решению](00_ГЛОБАЛЬНЫЙ_ПЛАН_К_ЭТАЛОНУ.md)** — единственный актуальный план по данным, модели, backend и следующим шагам. Файл находится в корне репозитория.

Исследовательская система для прогноза пассажиропотока и прототип backend API. Проект содержит FastAPI, PostgreSQL, отдельный worker и ML-код. Цель конкурсной модели — общий поток по маршруту и часу; текущие файлы не доказывают возможность достоверно оценить посадку/высадку на каждой остановке.

## Запуск полного стека через Docker

На macOS или Linux распакуй архив в корень проекта так, чтобы появились `dataset/labels/labels_day_train.csv`, `dataset/labels/labels_day_test.csv` и `dataset/test_submission.csv`. Затем запусти `sh scripts/start-stack.sh`. Скрипт поднимает PostgreSQL, применяет миграции, публикует факты из меток, обучает почасовую модель на CPU и запускает API с собранным фронтендом и worker.

Открой [http://localhost:8000](http://localhost:8000) и войди как `tram-admin`. Пароль лежит в локальном `.env` под `TRAM_BOOTSTRAP_OPERATOR_PASSWORD`. Подробности команд и проверка числа строк описаны в [запуске Docker](docs/DOCKER_STACK.md).

## Что уже находится в коде

- **Backend**: FastAPI, PostgreSQL, OpenAPI, очередь заданий и worker. Worker загружает активную модель из `models/tram/`, проверяет SHA-256 и использует `ArtifactPredictor`.
- **Трамвайный пайплайн**: Модульная архитектура в [`ml/training/tram/`](ml/training/tram/) (`features.py`, `baseline.py`, `models.py`, `evaluation.py`, `bundle.py`, `submission.py`, `cli.py`) с обратной совместимостью через [`ml/training/train_tram.py`](ml/training/train_tram.py).
- **Внешние данные**: Полный почасовой архив погоды Москвы Open-Meteo за 2025 год (`data/weather_hourly_2025.csv`) и производственный календарь РФ № 1335 (`data/calendar_2025.csv`).
- **Контроль сабмитов**: Замороженный baseline в `ml/predictions/baseline/`, строгий валидатор [`scripts/validate_submission.py`](scripts/validate_submission.py) (проверка 14 640 строк, 10 маршрутов, нулевого маршрута 5, структуры колонок и отклонений).
- **Бенчмарк производительности**: Скрипт [`scripts/benchmark_inference.py`](scripts/benchmark_inference.py) для регулярного замера latency (p50/p95/p99), RPS и памяти с сохранением в `benchmarks/latest.json`.
- **Эксперимент метро**: `ml/training/prepare.py`, `train.py`, `evaluate.py` обрабатывают квартальные данные из наборов Москвы 624/62743. Это изолированная квартальная задача, отделённая от трамвайного соревнования.

## Что делать с внешними данными

Дополнительные источники дают признаки, но не заменяют метки целевого ряда. Почасовой архив погоды Open-Meteo и официальный календарь РФ с переносами выходных уже загружены в `data/` и подключены к генерации признаков. Трафик Москвы и архив событий — условные источники: наличие живой страницы/API или текущего события ещё не подтверждает историческое покрытие для обучения. Каждый источник оценивается отдельной временной абляцией.

Организаторы подтвердили, что `bus_stop_no` не даёт надёжного соответствия валидации остановке, а остановочная детализация опциональна. Основной результат — общий поток по маршруту. Маршрут 5 остаётся в сабмите: по правилам организатора он строго заполняется нулями (`prediction=0`).

## Основные команды запуска

Из корня репозитория на Windows/PowerShell:

### 1. Установка окружения
```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt -e .

# Опционально: установка ML-библиотек для обучения CatBoost/LightGBM
python -m pip install -e .[training]
```

### 2. Запуск сервисов
```powershell
# Старт HTTP API и Swagger UI (http://127.0.0.1:8000/docs)
tram serve

# Старт фонового воркера прогнозирования (с активным ArtifactPredictor)
tram worker --once
```

### 3. Обучение, экспорт и валидация моделей
```powershell
# Обучение и экспорт бандла (baseline, histgradient или catboost)
python ml/training/train_tram.py --model baseline

# Валидация конкурсного файла предсказаний
python scripts/validate_submission.py ml/predictions/submission.csv

# Запуск бенчмарка задержки и пропускной способности инференса
python scripts/benchmark_inference.py --iterations 10
```

### 4. Проверка работоспособности API
```bash
curl -X GET "http://127.0.0.1:8000/api/v1/health"
```
