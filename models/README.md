# models — будущие версии обученных моделей

**Обученных моделей здесь пока нет.** Действующая сезонная база реализована кодом в `ml/src/tram_ml/baseline.py` и не требует весов. Эта папка подготовлена как место результатов будущего обучения, а не как доказательство, что обучение уже выполнено. Содержимое исключено из Git, кроме README.

## Что должно поступать сюда

Принятый или проверяемый кандидат из отдельного процесса обучения: артефакт + преобразования признаков + метаданные эксперимента. Исходные датасеты остаются в `sources/`, производные выборки — в `data/`. План процесса: [TRAINING_PLAN.md](../docs/TRAINING_PLAN.md).

## Предлагаемый состав версии

Ниже проект будущего формата; текущий worker его ещё не читает. Имена и расширение артефакта окончательно выбрать вместе с обучающей библиотекой и загрузчиком.

| Будущий файл в `<model-version>/` | Содержимое |
|---|---|
| `artifact.<format>` | Параметры модели и необходимые преобразования либо явные ссылки на их файлы. |
| `metadata.json` | Метод, версия модели/кода, версия данных, SHA-256 файлов, даты train/validation/test, фактическое время обучения и доступности. |
| `features.json` | Имена, типы, порядок, единицы, правила лагов/окон, обработка пропусков и неизвестных категорий. |
| `config.json` | Параметры обучения, seed, горизонт, частота, целевой показатель, правила splits. |
| `metrics.json` | Candidate и baseline на одинаковых folds/срезах, покрытие, исключённые точки, MAE/WAPE. |
| `environment.txt` | Точные версии Python и библиотек, нужные для воспроизведения. Не заменяет основной requirements.txt. |
| `model-card.md` | Назначение, происхождение меток, ограничения, качество, решение о допуске и ответственный за ревью. |

## Что сделать после обучения

1. Проверить повторное чтение артефакта: прогноз до и после сохранения совпадает в заданном допуске.
2. Сверить схему признаков, версию данных и контрольные суммы. Использовать только доверенные артефакты; некоторые форматы сериализации способны выполнять код при загрузке.
3. Сохранить решение по качеству; наличие файла не означает допуска к использованию.
4. Подключить адаптер `Predictor` и регистрацию метода в [backend](../backend/README.md). Сейчас допускается только `seasonal_naive_v1`; переименование метода в manifest не реализует загрузку модели.
5. Проверить API → worker → результат, метаданные версии, отказ при несовместимости и правила возврата к предыдущей версии. Обучение остаётся вне HTTP-запросов.

Версию не перезаписывать: новый набор/код/параметры дают новый каталог. `available_at` — реальная доступность модели, а не начало её обучающей истории. До создания и проверки загрузчика API не обращается к этой папке.
