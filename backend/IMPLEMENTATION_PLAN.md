# План реализации Backend (API Эндпоинты)

В данном документе перечислены все эндпоинты (на основе `openapi.yaml`), которые необходимо реализовать на бэкенде для обеспечения полной работы фронтенда.

## System (Готовность, возможности и свежесть)

- [ ] **`GET /api/v1/health`**
  - **Описание:** Публичная проверка готовности API и БД без секретов.
  - **Ответ:** 200 OK (или 503, если БД недоступна) со схемой `Health`.
  
- [ ] **`GET /api/v1/capabilities`**
  - **Описание:** Доступные показатели и профили (вычисляются из аудита данных и реестра моделей).
  - **Ответ:** Список `forecast_profiles` и `observation_profiles`.

- [ ] **`GET /api/v1/data-status`**
  - **Описание:** Свежесть данных и режим источника (опрос фронтендом для вывода плашки "ДЕМО" и версий).
  - **Ответ:** Состояние ревизий датасетов и сети, список `sources` со статусом `freshness`.

## Catalogs (Версионированная маршрутная сеть)

- [ ] **`GET /api/v1/routes`**
  - **Описание:** Список маршрутов на указанную дату (`valid_at`) и версию сети (`network_revision_id`).
  - **Ответ:** Пагинированный список с краткими данными (id, number, name).

- [ ] **`GET /api/v1/routes/{route_id}`**
  - **Описание:** Полная топология одного маршрута (включая остановки, направления и координаты).
  - **Ответ:** Объект маршрута с массивами `stops` и `directions` (GeoJSON геометрии).

- [ ] **`GET /api/v1/stops`**
  - **Описание:** Справочник уникальных остановок.
  - **Ответ:** Пагинированный список остановок.

## Observations (Фактические и восстановленные значения)

- [ ] **`GET /api/v1/observations`**
  - **Описание:** История наблюдений за выбранный период (from, to). Возвращает массив интервалов с пассажиропотоком.
  - **Ответ:** Пагинированный список `items` с полями `interval_start`, `route_id`, `value`.

## Forecasts (Асинхронные расчёты и неизменяемые результаты)

- [ ] **`POST /api/v1/forecast-runs`**
  - **Описание:** Создать задание прогноза (требуется роль operator). Ставит задачу в очередь worker'а.
  - **Ответ:** 202 Accepted (если в очереди) или 200 OK (если уже есть готовый результат).

- [ ] **`GET /api/v1/forecast-runs`**
  - **Описание:** Поиск сохранённых запусков прогнозов с возможностью фильтрации.
  - **Ответ:** Список статусов запусков.

- [ ] **`GET /api/v1/forecast-runs/{run_id}`**
  - **Описание:** Получение текущего статуса конкретного задания прогноза (queued, running, succeeded, failed).
  - **Ответ:** Объект состояния прогноза.

- [ ] **`GET /api/v1/forecast-runs/{run_id}/points`**
  - **Описание:** Получение массива предсказанных точек для графика (только если статус succeeded).
  - **Ответ:** Список интервалов и значений `value`.

- [ ] **`GET /api/v1/forecast-runs/{run_id}/map`**
  - **Описание:** GeoJSON прогноз одного интервала для отображения на карте.
  - **Ответ:** `FeatureCollection` точек/линий.

## Evaluations (Временная проверка качества)

- [ ] **`GET /api/v1/evaluations`**
  - **Описание:** Список отчётов проверки качества моделей на исторических данных.
  - **Ответ:** Список объектов Evaluation.

- [ ] **`GET /api/v1/evaluations/{evaluation_id}`**
  - **Описание:** Получение конкретного отчёта (метрики, базовые методы, ограничения).
  - **Ответ:** Детальный отчёт качества.

- [ ] **`GET /api/v1/evaluations/{evaluation_id}/points`**
  - **Описание:** Массив исторических данных (факты) и предсказаний для отображения исторических графиков.
  - **Ответ:** Списки точек факта (`actual`) и предсказаний (`model`).

## Задачи инфраструктуры

- [ ] **Модуль Auth & RBAC:** Поддержка роли `operator` .
- [ ] **Очереди и Worker (Celery / RQ / и т.д.):** Асинхронное выполнение ML-расчётов.
- [ ] **Интеграция БД (PostgreSQL/PostGIS):** Хранение GeoJSON-маршрутов и истории пассажиропотока.
