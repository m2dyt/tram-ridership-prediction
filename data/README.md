# data — подготовка и публикация данных

Здесь находятся производные данные: синтетическое демо, очищенные таблицы, отчёты качества, наборы для публикации и будущие выборки обучения. Оригиналы остаются в [sources](../sources/README.md). Содержимое `data/` исключено из Git, кроме этого README.

## Что уже создаёт приложение

`demo-complete/` — текущий локальный демонабор; он синтетический. При новом клонировании его нужно создать командой из [главного README](../README.md). Ранее созданный `demo/` может содержать старую версию демонстрации, это не второй независимый реальный датасет.

| Файл внутри демонабора | Кто создаёт / читает | Зачем |
|---|---|---|
| `manifest.json` | `demo` → `publish` | Версия данных, сеть, источники, модели, профили и пространственные ряды. |
| `observations.jsonl` | `demo` → `publish` | Временные точки наблюдений с профилем, доступностью, значением и качеством. |
| `request-day.json`, `request-month.json`, `request-year.json` | `demo` → оператор/API | Примеры постановки прогнозов для соответствующего горизонта. |
| `trip-plan.json` | `demo` → `replay-trip` | Вагон, направление, остановки, времена, вместимость и начальный остаток. |
| `trip-events.jsonl` | `demo` → `replay-trip` | Последовательность входов/выходов на остановках. |
| `context-request.json` | `demo` → `context-refresh` | Запрос внешнего контекста. |
| `evaluation-origins.json` | `demo` → команды `evaluate` | Отсечки для полного исторического прогноза. |

Основной формат публикации: [DATA_FORMAT.md](../docs/DATA_FORMAT.md). Формат CSV: [OPERATIONS.md](../docs/OPERATIONS.md). `publish` принимает подготовленный каталог, а не произвольную таблицу Москвы.

Дополнительно создан **`quality/moscow-20260921/audit.json`**: первичная проверка реальных выгрузок 624/62743, SHA-256 входов, число строк, поля/пропуски, дубли, покрытие кварталов, координаты и точное сопоставление названий. [Выводы и следующий шаг](../docs/DATA_AUDIT.md). Это отчёт, а не нормализованный обучающий ряд; исходники находятся в sources/data-mos.

## Подготовленные реальные данные метро

Команды и повторяемый порядок запуска — [METRO_PIPELINE.md](../docs/METRO_PIPELINE.md). Они работают без БД и не обучают модель. После клонирования каталоги нужно создать заново из оригиналов с паспортами происхождения.

| Локальный каталог | Файлы и их роль |
|---|---|
| `metro/moscow-20260922/` | `entrances.geojson` — все 1 177 входов со статусами; `series.json` — 315 пар станция/линия и связи с входами; `quarters.jsonl` — 6 930 точек с явными пропусками; `quality.json` — проблемы и принятые правила; `manifest.json` — происхождение, версия и SHA-256. |
| `metro-evaluation/seasonal-20260922/` | `splits.json` — полуоткрытые train/validation/test; `membership.jsonl` — принадлежность точек; `predictions.jsonl` — факт, прогноз и опорный квартал; `scores.json` — ошибки/покрытие; `manifest.json` — входная версия, метод и ограничения. |

Это файловые исследовательские форматы, не вход для трамвайного `publish`. Нули не удалены, пропуски не заполнены, неоднозначные станции не склеены. ID относится к точной паре исходных названий; физические станции и переименования ещё требуют проверки. База использует прошлогодний квартал, географию в прогноз не включает. Подробный словарь файлов и политика — в инструкции выше.

## Куда складывать следующие результаты

Ниже **соглашение для следующих этапов**. Эти каталоги/артефакты ещё не подготовлены; уже созданные результаты метро описаны отдельно выше:

```text
data/
  normalized/<версия>/       # очищенные таблицы и таблицы соответствия ID
  quality/<версия>/          # словарь колонок, покрытие, дубли, пропуски, спорные строки
  prepared/<версия>/         # manifest.json + observations.jsonl для publish
  training/<версия>/         # task.md, splits.json, features.json и обучающие таблицы
  evaluations/<эксперимент>/ # файловые результаты будущего обучения/backtesting
```

Текущий `evaluate` публикует отчёты в PostgreSQL, а не в `data/evaluations/`. `evaluate-metro` сохраняет отдельный квартальный отчёт в заданный каталог; это не экспорт отчёта трамвайного API.

## Последовательность работы

1. Прочитать файлы из `sources/`, проверить типы, кодировку, единицы, время и уникальность ключей. Записать отчёт в `quality/`.
2. Сопоставить внешние ID с версией сети. Сохранить таблицу соответствия и неподтверждённые совпадения; не соединять станции только по похожим названиям.
3. Выбрать целевую величину. Для посадок агрегировать события; для наполненности сначала получить журнал рейсов и остаток пассажиров. Для метро 62743 сохранить квартальную частоту вне текущего API.
4. Сформировать поддерживаемую временную сетку, сохраняя пропуски с причиной, `observed/estimated`, `available_at` и источник.
5. Для API подготовить manifest и CSV точного формата; `prepare-csv` переведёт его в JSONL. Он не выполняет шаги очистки 1–4 вместо разработчика.
6. Проверить набор и опубликовать; для обучения следовать признакам и временным splits из [глобального плана проекта](../00_ГЛОБАЛЬНЫЙ_ПЛАН_К_ЭТАЛОНУ.md).

Следующие команды — **шаблон после подготовки указанных файлов**, сейчас эти примерные пути не существуют. Выполнять из корня, выходной каталог выбирать новый:

```powershell
python -m tram.cli prepare-csv data/normalized/tram-v1/manifest.json data/normalized/tram-v1/aggregates.csv data/prepared/tram-v1
python -m tram.cli publish data/prepared/tram-v1
```

`prepare-csv` отвечает за формат; семантика, дубли, связи и полный охват проверяются при публикации. Исправление — новый выходной каталог/ревизия. Публикация делает ревизию последней для запроса capabilities без ID; это следует учитывать при работе с уже заполненной БД.

`export-occupancy` уже может получить prepared bundle из сохранённых рейсов. Его результат помечен `estimated`, содержит профили истории и сам не включает прогноз. [Пример экспорта](../docs/OPERATIONS.md).

## Когда переходить в ml

Есть словарь полей и отчёт качества, согласованные ID/время, достаточная история, независимая проверка меток и фиксированная версия. Не использовать демо для доказательства качества. Не считать сегодняшнее получение исторического файла доказательством его доступности в прошлом. Далее: [ml/README.md](../ml/README.md).
